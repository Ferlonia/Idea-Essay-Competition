# Guide to Figures, Schemes, and Tables for Idea Essays

Contents: why figures, catalog of types, choosing one main type, figure rules in the manuscript, figure specification (output format), how to make them, traps.

## Why figures
In the example essays, figures and tables always support one message to the judge: a workflow that can be run, a clear device design, a visible prototype, the parties involved, or a phased plan. A figure lets the judge understand at a glance, so the text does not need to explain again. Figures are part of creativity, but they use up page space, so they are chosen, not piled on.

## Catalog of types (from the photos, with additions)
| Type | Content | Question from the judge it answers | Example in the photos |
|---|---|---|---|
| T1 Workflow | Numbered boxes, 3-6 steps with arrows, possibly with a cycle arrow | "How is this run?" | A four-step flow figure that repeats every season |
| T2 Labeled device design | Cross-section or front view with a label line for each component | "What does the device look like and what does each part do?" | A simple device design made from used materials |
| T3 Product prototype/mockup | Front and back of packaging or a design, with the distinctive elements | "What does this idea look like in physical form?" | Product packaging with an educational QR code |
| T4 App mockup and user flow | 3-5 key screens, or a user-flow diagram | "What does the user see and do?" | [ADDED] |

T1-T7 are figures. T9 is a table treated like a figure (numbered, sourced). T8 only if the figures are sourced.

## Choosing one main type
Each manuscript chooses one main figure that answers the question "how does this work", then adds at most one or two supporting figures if the pages allow. Reason: the page limit is usually 7, the introduction and discussion are already dense, and one figure the judge reads is better than four the judge skips.

Steps to choose:
1. Determine the type of idea.
2. Take the main type from this table:
| Type of idea | Main figure | Supporting (if there is room) |
|---|---|---|
| Device or technology | T2 labeled design | T1 workflow, T9 stages |
| Product (food, packaging, material) | T3 prototype | T1 production flow, T5 stakeholders |
| App or website | T4 user flow/mockup | T5 managing party |
| Program, method, system, policy | T1 stage flow or T5 actor scheme | T7 roadmap, T9 comparison |
| Social/legal idea based on a mechanism | T5 actor scheme and flow | T1 |
3. Test with one question: if the judge sees only this figure, can they retell how the idea works? If not, change the type.
4. If two types are equally strong, pick the one that shows what the judge is least likely to believe. For an idea that sounds ambitious, that is usually the workflow or design; for an idea that sounds ordinary, it is the differentiator (comparison).

## Figure rules in the manuscript
- Sequential number and caption: "Figure n. [Short explanation]" below the figure; "Table n. [Explanation]" above the table. Numbers must not jump.
- Cited in the text before it appears: "The workflow is presented in Figure 1."
- Source: "Author's documentation" or "Illustration of the author's design (year)" for your own figures; "processed from Name (year)" for other parties' data. A design is a concept illustration, not a photo of test results; do not make it look like experimental evidence.
- Readable when printed in black and white, label font not under 8 pt, short labels (1-3 words), at most 3-4 colors.
- One figure, one message. Split the workflow and the device design into two figures if the labels get crowded.
- Place the figure right after the paragraph that cites it; if it does not fit within the page limit, move it to the appendix and refer to "Appendix n".
- If the guidelines restrict or regulate AI-generated figures, follow the guidelines, and state in the caption that it is a design illustration. Ask the user if the guidelines are unclear.

## Figure specification (output format when requested)
When the user asks for a figure, produce this specification first so it can be approved, then make it:
- Figure number and caption
- Type (T1-T7) and the reason it was chosen
- Exact elements and labels (list of texts, order, arrow direction)
- Style: clean lines, 3-4 colors, white background, flat style
- Placement in the manuscript (after which paragraph) and size (column width or half page)
- Source/caption
- A prompt for an image tool (if needed), with no brand names or characters, and no long text inside the image (text in AI-generated images is often misspelled; add the labels yourself)

## How to make them
1. If a code tool is available (Mermaid, SVG, or a chart library), build flow diagrams, schemes, and roadmaps in code so labels are exact and easy to revise, then export a high-resolution PNG.
2. For prototypes and device designs, sketch with boxes and label lines (SVG) if there is no drawing tool; or give the specification above so the user can draw it in Canva, draw.io, or Figma.
3. For realistic illustrations from an image-generation tool, use them only for T3, and check the result: labels, spelling, and match with the design.
4. Check after it is done: labels match the text, terms are the same as in the manuscript, the number and source are there, and it stays legible when reduced.

## Traps
- Putting more than three figures in a 7-page manuscript so the discussion text gets cut.
- A figure that explains something different from the text (different terms).
- Small, dense labels that cannot be read when printed.
- A decorative figure with no message.
- Photos or logos that violate copyright; use your own work or licensed material.
